# Подготовка публикации

Публикуется только отдельный source repository. Нельзя копировать сюда старую `.git` историю, авторизованный prefix, runtime, игровые файлы, собранное локальное app или `data-location.txt`. `.gitignore` — дополнительный барьер, а не доказательство отсутствия данных.

Разделение:

- Публично: исходники MIT, LGPL DXMT diff, notices, начальный пресет эффектов, dependency lock, обезличенная документация/тесты. Игровой профиль управления/графики не входит в исходники.
- Приватно: все скачанные/собранные бинарные компоненты, prefix, EA auth/cookies, игра, пользовательский preset, PROFSAVE, локальный config, logs/CSV/скриншоты, app с адресом private data.

Перед публикацией:

```sh
python3 -B -m unittest discover -s tests -v
python3 -B scripts/privacy_scan.py
python3 -B scripts/package_source.py ../bf4-macos-source.zip
python3 -B scripts/privacy_scan.py --archive ../bf4-macos-source.zip
```

Scanner использует **точный список 31 исходного файла**, запрещает неожиданные файлы внутри каталогов и ссылки на каталоги/файлы, binaries/logs/private file types. Проверяет текущий login/home, персональные пути и адреса почты, credential/cookie/key/VPN patterns. Он читает **все Git objects**, включая недостижимые и reflog-only, записи reflog, локальный Git config и source archive. Найденные значения не печатаются. Это ограниченная проверка закономерностей, не математическое доказательство отсутствия любого неизвестного секрета. Поэтому основная защита — новая история и явный source allowlist, отсутствие импорта private state и ручной просмотр diff. При добавлении исходника обновите `PUBLISH_FILES` осознанно; не разрешайте целую папку пользовательских данных.

Git author для подготовительной локальной истории должен быть нейтральным `BF4 Portable contributors <contributors@example.invalid>`; исходный пользовательский git config не переносится. Не используйте аккаунт EA или Mac login как автора/название branch. Для публикации экспортируйте проверенный source ZIP в отдельный repository с новой нейтральной историей, без экспериментальных commits рабочей папки. Remote задаётся только для выбранного проекта; credentials не включаются в URL. Если найден private object, не добавляйте «удаляющий» commit поверх него: создайте заново чистый отдельный repository из проверенного allowlist.

`package_source.py` не включает Git metadata, binaries или private data и проверяет получившийся архив. Релиз готового локально сконфигурированного `.app` запрещён этим процессом: его Resources содержит приватный указатель хранилища, а права на сторонние binaries должны проверяться отдельно. Не создавайте GitHub release из рабочей папки/префикса.

Перед готовым релизом VALIDATION должна содержать реальные чистые и игровые проверки, варианты опций и запуск после reboot. Если строка pending/failed, не объявляйте сборку проверенной/готовой. Публикуемый до завершения проверки кандидат должен быть явно обозначен как кандидат. Upload, push, remote, release или GitHub account action выполняются только по запросу владельца.
