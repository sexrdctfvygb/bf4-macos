## Происхождение DXMT изменений

- База — указанный полный upstream commit.
- Инициализация Wine/native-window: [elseform commit 35c6ed4](https://github.com/elseform/dxmt/commit/35c6ed4983577c64a07e5569aec95eb2247af357), [upstream PR 166](https://github.com/3Shain/dxmt/pull/166), commit `a1aa73fd8a8569edcc83378804f94dfbdcfcea10`. Изменения сведены в один diff без личных заголовков почтового patch.
- BF4 buffer RTV compatibility / null guard: малые изменения по поведению [DXVK-macOS D3D11](https://github.com/Gcenx/DXVK-macOS/tree/master/src/d3d11), с сохранением LGPL условий изменённого DXMT. Это workaround ограниченного случая BF4, не полная поддержка buffer RTV.
- Локальный GetDesktopWindow перед fullscreen и опциональная BF4-only Present telemetry; исходники полностью в cumulative patch.
- Сборочные изменения PE-only исключают native LLVM/Metal build: используются **точные проверенные** native/shader assets из выбранного template. Это ABI-связанный комплект; не заменяйте произвольной версией DXMT.

В `licenses/` лежат DXMT LGPL тексты и SweetFX MIT. Если проект станет распространять compiled DXMT, Wine или любые другие binaries, нужны соответствующие исходники/уведомления/возможность relink и отдельная проверка каждого артефакта. Текущий проект сознательно публикует source recipe; готовое локально установленное приложение и runtime являются пользовательскими данными.

`assets/WorkingSweetFX.fx` — небольшой проектный MIT adapter; он вызывает функции авторов CeeJay.dk / 3an и не содержит их тела. Значения параметров и порядок соответствуют рабочему четырёхэффектному варианту. `legacy_headers` в lock проверяет точное содержимое каждого скачанного header; путь из архива не распаковывается на диск, извлекается только содержимое четырёх заранее названных файлов.

EA App 13.805.11.6320: URL и размер MSI получены из Burn manifest закреплённого официального bootstrapper. При первичной проверке совпал SHA-1 payload из manifest; для установки используется отдельный закреплённый SHA-256 MSI. В Wine этого комплекта bootstrapper не создаёт свой диалог. Установка через штатный `msiexec` с собственной bundle registration завершилась с кодом 0; это обход сбоя установочного UI, а не изменение проверки аккаунта/лицензии EA. Клиент авторизуется заново локально и может затем обновиться штатно.

SweetFX/ReShade дополнительно использует native x64 D3DCompiler 43 из легальной копии BF4: `redists` запускает её официальный DXSETUP. Проверяются PE-архитектура, отсутствие маркера builtin Wine и расположение внутри собственного префикса; это проверка пригодности установленного файла, а не криптографическое подтверждение всего пользовательского игрового каталога. Библиотека Microsoft не копируется из прежнего префикса и не распространяется здесь. Выбор 43 выполняется app-specific override: [ReShade 6.8.0](https://github.com/crosire/reshade/blob/v6.8.0/source/dll_main.cpp) поддерживает этот fallback при недоступном 47. Для данного комплекта переход восстановил отрисовку и компиляцию 28 SweetFX-файлов после чёрного экрана; точная внутренняя причина зависания builtin 47 не установлена.
